# Henge · 词句修订

适用于 SillyTavern 的纯规则词句修订扩展。回复输出结束后按规则自动修订，或按正文顺序展示建议供你审阅。支持 JavaScript 正则、随机替换候选和酒馆替换宏。**不调用聊天模型，也不需要 API Key。**

扩展管理列表中的名称为 **Henge**；功能面板和魔棒入口仍显示「词句修订」。仓库名为 `sillytavern-text-revision`，安装地址保持不变。

## 功能介绍

| 功能 | 可以做什么 |
| --- | --- |
| 词语与句式检测 | 直接填写词语或句式正则，多个替换候选随机选择，留空删除 |
| 规则集分享 | 将全部规则导出为 JSON 文件；导入时选择追加或替换全部 |
| 检测范围 | 提取正文标签；通过开始、结束文字排除标签或其他片段 |
| 逐句审阅 | 删除划线、新增和待改分色显示；点击整条选择或取消，右上角小铅笔编辑整句，三点菜单可恢复原句或删除整句 |
| 指定楼层检测 | 每条 AI 回复的编辑铅笔左侧有方框铅笔入口，可检测最新或历史楼层；本次面板内重新检测仍跟随所选楼层 |
| 应用与撤销 | 一次应用所选，更新保存的正文和当前回复版本，并支持撤销最近一次应用 |
| 检测记录 | 同楼按内容版本显示为 `10# 1`、`10# 2`；最近 10 层保留句段详情，最多 99 层保留修改日志 |
| 手机与外观 | 加宽侧栏、魔棒菜单入口、可拖动悬浮球、日夜模式、四种界面美化、三组修订配色、背景透明度 |

版本变更见 [更新日志](CHANGELOG.md)。

检测完成后立即显示结果；检测记录在后台保存，期间可以选择、编辑和继续审阅，保存结束不会重刷列表或打断编辑。自动应用把检测记录、修改日志和正文合并为一次保存；实际应用、撤销和完成审阅仍会等待保存确认，期间保留必要的操作保护，文字不再整体变暗。

第一次使用或需要转发给其他用户时，可直接阅读 [Henge 使用教程](使用教程.md)。教程从安装、第一条规则和审阅流程讲起，并用实际例子解释正则中的 `?`、`|`、括号与 `$1` / `$2`。

## 安装

1. 在电脑或手机的酒馆中，打开「扩展」→「安装扩展」。
2. 粘贴 `https://github.com/Mint0oO/sillytavern-text-revision`，完成安装后刷新酒馆。
3. 点击输入框左侧的魔棒，在菜单中选择「词句修订」。也可从扩展设置打开、输入 `/text-revision`，或点击某条 AI 回复编辑铅笔左侧的方框铅笔图标检测该楼。需要常驻入口时，在插件设置中开启「显示悬浮球」。

需要 SillyTavern 1.13.5 或较新版本，以及支持原生 dialog 的现代浏览器。若酒馆没有「安装扩展」，需要服务器管理员允许扩展安装；不需要在手机上安装 Node.js。

## 使用

- 自动检测：标为自动的命中先应用并保存，剩余需要审阅的内容再打开侧栏。主面板未打开时，全部自动处理完成不会弹面板；若新回复完成时主面板正在审阅另一楼，则先等待，关闭当前主面板后再检测并展示新回复（包括无问题或已自动处理完成的状态）。重复完成通知合并处理；重 roll 后会检测新的回复。检测不调用模型，普通长度回复通常很快完成，保存时间取决于酒馆连接。
- 普通入口在每次打开主面板时选择当时最新的可检测 AI 回复；方框铅笔入口选择被点击的楼层。面板中的「重新检测」始终检测本次所选楼层，进入规则、设置或记录后再返回也不会跳楼。只有关闭主面板或切换聊天才结束本次选择。
- 面板改为屏幕中央弹出，四周保留安全留白，最宽 1040 像素；窄屏自动缩小留白，不贴住屏幕边缘。
- 点击有可应用建议的整条内容，可选择或取消；右上角小铅笔与三点按钮只占第一行。三点菜单可恢复原句或删除整句；取消选择即可保留。点击铅笔后可在原句下方编辑整句。未完成输入在本浏览器会话中保留，刷新后同楼、同版本且正文和规则未变时可恢复。
- 规则的替换框留空表示删除；审阅候选中的「换一个」可选择其他替换词，每个候选旁也始终提供「删除」。
- 默认勾选有可应用建议的句子；取消勾选的句子不会改动。「应用所选」一次处理全部勾选项，保存成功后本轮不再显示角标。完全不想修改时可点「完成审阅」；剩余文字保留，之后仍可主动重新检测。
- 应用直接更新 `chat[].mes` 和当前 `swipes[swipe_id]`，调用酒馆保存，再读取服务器聊天核对。后续请求使用修改后的正文；其他版本不变。
- 「撤销」恢复本轮最近一次应用。切换聊天、回复版本、外部编辑或重新检测后，过期结果不能覆盖当前正文。
- 「记录」按 AI 楼层和内容版本合并，重复检测不另占名额；最近 10 层保留句段详情，第 11–99 层仅保留修改日志，第 100 层淘汰最旧整层。旧记录转换后先保留旧副本，可在记录页导出备份再清理。候选全集不写入新记录；累计检测次数另计。
- 「规则」标题右侧显示“已启用数量 / 总数”；下方保留搜索、删除、新增、导入和导出；搜索约占一行宽度的三分之一，手机保留最小输入宽度，空间不足时操作按钮整体换行。工具栏下方用文字显示自动检测状态，不再提供跳转按钮；搜索框右侧常驻清空叉号，输入后可一键清空。点击「删除」后可勾选一条或多条规则，取消与确认操作固定在底部。列表用 `*` 隐藏正则括号组和任意内容结构的细节，并把超长规则限制为一行；平时点击条目会打开独立编辑弹窗。启用勾选位于最右侧，与编辑操作独立；已有规则可在编辑框左下角单独删除。右上角关闭编辑框，存在未保存修改时会先询问是否放弃。
- 「导出 JSON」下载当前全部规则和统一处理方式，适合备份或分享；不会导出聊天正文、检测记录、标签提取、内容排除和外观设置。「导入 JSON」先读取并校验文件，再选择追加或替换全部。追加会保留现有规则和当前处理方式，并跳过重复项；替换全部会清除现有规则并采用文件中的处理方式。
- 新规则直接填查找和替换，填法与示例见下方「填写查找和替换」。
- 「设置」按运行设置、检测范围、界面外观分组。「启用插件」控制整个插件；「自动检测」控制回复完成后的触发；「显示逐楼层检测入口」只控制每条 AI 回复旁的图标；「处理方式」决定人工审查或自动应用。悬浮球关闭时隐藏其颜色和透明度选项，重新开启仍保留原设置。
- 悬浮球缩小为 36 像素圆形，可选择跟随美化、石墨、浅蓝、鼠尾草、淡紫、奶茶配色，并独立调整整个图标的透明度；设置中提供实时预览。可用鼠标或手指拖动；位置在当前设备浏览器中记忆，屏幕变化时保持可见。轻点打开面板，拖动不会打开。
- 顶部显示「x处问题/x字段　楼层号#」；字段指可独立修订的句段。记录中的 `楼层# 版本` 是该楼已记录的内容版本编号，不是检测次数。

## 标签提取与排除

在「设置 → 检测范围」中，「标签提取」和「内容排除」同排各占一半。点击对应入口会打开独立弹窗，点「保存」生效；「取消」不保存本次修改。两个功能各有开关，关闭时保留配置，方便以后再开启。

- **标签提取**：例如填 `content, maintext`，只检查对应标签内部的文字。使用逗号、中文逗号或换行分隔，也接受 `<content>` 或 `</content>`，大小写不敏感。支持 `Time-Space Module` 这样的带空格自定义标签名。关闭或留空表示整条回复；启用并填写了标签但回复中找不到时，会跳过，不会退回全文检测。
- **内容排除**：每行填写开始和结束文字，排除这两个标记及中间内容。例如 `<status>` → `</status>`、`image###` → `###`。可以添加和删除规则。排除优先于提取，包括正文里面的嵌套内容。
- 标准标签对支持大小写、属性和同名嵌套；其他分隔文字按原样匹配，区分大小写。请把需要保护的边界符号填完整。开始文字出现却没有对应结束文字时，会提示并停止检测。
- 默认提取标签为空；默认仅排除 `think`、`thinking`，以成对规则展示。旧版排除标签会自动转为可编辑规则；未改动过的五项默认列表会精简，自定义列表会保留。
- 不填写正文标签也可以检测：关闭或留空「标签提取」，再排除非正文内容，剩余文字就会参与检测。这是按配置筛选，不会自动判断剩余内容是不是正文；状态栏等内容如需跳过，须自行添加排除。

例如提取 `content`、排除 `status`：

```xml
<think>极其谨慎地思考。</think>
<content>
你拖着极其疲惫的身体，走进了旅店。
<status>情绪：极度不安</status>
壁炉旁的空位极具吸引力。
</content>
```

检测列表只出现「你拖着……」和「壁炉旁……」两段。`think`、`status` 里的内容以及全部标签原样保留。多个正文块会按原顺序处理；属性和原始换行不会被重新格式化。

标签、代码和排除内容构成编辑边界。一个句子中间含有这些内容时，会拆成独立句段，手动编辑也不会带上被保护内容。句式不会跨越这些边界匹配。配置的标签未闭合或配对错误时会停止检测并提示，修正原回复后再试。

保存新的检测范围后，需要重新检测；旧范围下的结果不会继续覆盖正文。标签设置仅改变检测范围，不会在未来请求中删除标签或排除内容。

## 填写查找和替换

规则编辑始终显示「查找」和「替换为」两个框，不再要求选择字词／句式、处理方式、词性或模板。新规则统一使用正则匹配，不调用 AI，也不需要生成脚本。

| 查找 | 替换为 | 效果 |
| --- | --- | --- |
| `死死` | 留空 | 删除每一处「死死」 |
| `死死地?` | 留空 | 删除「死死」和「死死地」 |
| `极其, 极致` | `十分, 很` | 每处随机换成「十分」或「很」 |
| `不是([^，。！？]+)，而是([^。！？]+)` | `$2` | 保留括号匹配的后半段 |
| `，(?:声音\|尾音)[^，。！？]*` | 留空 | 删除以「，声音」或「，尾音」开头、到下一个指定标点之前的片段 |

查找直接填写 JavaScript 正则的表达式部分，程序默认开启全部匹配（`g`），不用手动填写 `/…/g`。也接受完整 `/表达式/标志`，并保留你明确填写的标志；例如 `/死死/` 不含 `g`，只匹配每个连续可编辑正文块中的第一处。

查找始终是正则规则。**表达式最外层的英文逗号和实际换行都用于分项**，把一条规则可视化地分成多个独立正则分支；每个分支仍可使用 `?`、`|`、括号、字符范围和反斜杠。例如 `死死地?, 极其` 与分成两行的写法含义相同，而且各分支中的 `$1`、`$2` 分别从头编号。前后空格会清理，重复分支去重。中文逗号始终按正文标点保留。

括号、字符范围和数量范围内部的逗号或换行不会被拆分，例如 `(甲,乙)`、`[a,b]`、`a{1,3}`。要匹配最外层的英文逗号可写 `\,`。完整 `/表达式/标志` 自身也保留原式，多个完整表达式可分别写在不同的行，例如 `/极其/g` 和 `/极致/g`；也支持 `/aaa/gi, 极其` 这样的混合写法，每项保留自己的标志。要匹配正文换行，推荐明确写 `\n`。规则列表收起时会把 `.*`、`.+`、`[^…]+`、`[\s\S]*` 等任意内容结构显示为 `*`，但编辑、导出和实际匹配仍保留完整正则。

替换框默认用英文逗号或换行分隔候选，每一处命中独立随机选择；填一个候选就固定替换，留空删除。候选含英文逗号时可用英文双引号包住，例如 `"轻轻, 缓缓", 低声`。中文逗号不拆分。

`$1`、`$2`、`$<名称>` 保留对应捕获组；`$&`、`$0` 或 `{{match}}` 放回命中原文。替换模板还支持 `{{user}}`、`{{char}}`、`{{random::轻轻::缓缓}}`，调用酒馆的宏接口。包含英文逗号的候选可用英文双引号包住。捕获的原文不会被再次作为宏执行。

「试一下」填写例句即可查看划线删除、新增文字及捕获内容，不会修改聊天；多个候选会随机选择，再点一次可重新试验。规则填写错误时保留草稿并提示原因。

## 执行、日志与规则兼容

在「设置 → 运行设置 → 处理方式」统一选择「人工审查」或「自动应用」，新建或重新保存的新格式规则跟随该设置。默认人工审查。设置中的「自动检测」控制是否在回复结束时启动检测。

新格式正则先在允许处理的连续正文中匹配，再按命中位置组织审阅句段；支持跨句和跨行，`^`、`$` 指连续正文块的边界，换行匹配仍遵循正则本身的语法和标志。标签、代码和排除内容始终是不可跨越的边界。空位置匹配、无效表达式、检测超时（3 秒）或结果过大时会停止，不写入部分修改。

各条规则检测同一份原文，不会对替换结果循环套用规则。互不重叠的命中全部执行；重叠删除会合并范围，包含关系只保留外层删除；删除与替换或两个替换重叠时，高优先级规则胜出，同优先级随机选出一套互不冲突的结果。仅提示规则参与重叠时仍保留人工审阅。自动结果保存后，仍需审阅的内容才打开面板；日志记录原文、结果、规则及自动／手动来源。候选及重叠裁决结果在本轮固定，保存和刷新不会重新随机；最近一次应用可以撤销。

旧字词、`{A}` 占位模板及词性、上下文条件不再执行。若配置中仍有这些规则，插件会保留原数据并阻止检测，规则页可导出原始备份，之后再删除或改写为正则。旧规则集中的纯正则可按旧格式导入；真正旧语义会停止整次导入。非默认优先级和整段替换设置仍保留在当前正则规则中。

新安装默认提供三条正则规则。升级用户原有规则列表不会被清空；旧检测结果只供查看，应用前需要重新检测。旧记录转换时保留可导出的原始副本。

正则按你填写的文字结构匹配，不判断句意。词语和句式都建议先用例句检查实际命中范围。

## 数据与兼容

规则和外观保存在酒馆扩展设置，检测记录保存在当前聊天元数据；记录只保留相关句段、修改日志和校验信息，不重复保存整条回复。它们不作为正文传给模型，导出聊天文件时会一并导出。旧记录迁移后，原始副本会暂时保留，需在记录页导出备份再清理。

扩展没有外部分析服务、跟踪脚本、远程字体或聊天模型请求；保存后会向你自己的酒馆读取聊天进行核对。手机通过局域网 HTTP 访问时也能生成内部记录编号。

如果出现「保存结果尚未确认」，请点击「重新确认」。服务器可能已收到保存但回读失败；在确认前插件暂停后续写入，避免覆盖未核对的正文。

同一聊天在多个设备同时编辑仍可能发生酒馆自身的并发冲突。建议只在一个设备上修改当前聊天。世界书、摘要、其他插件已缓存的旧内容不会被本扩展重写。

## 开发验证

无构建或安装依赖步骤。仓库根目录的 manifest.json 可直接被酒馆安装；需要支持正则匹配索引（`d` 标志）的现代浏览器。

```sh
npm test
npm run check
node scripts/dev-server.mjs
```

最后一个命令打开本地模拟酒馆界面：`http://127.0.0.1:8788`。模拟器可测试自动检测、保存、刷新读取、上下文正文和失败提示；它不是完整酒馆实例。`dev/` 与 `tests/` 不会由扩展入口加载。

接口依据：[酒馆扩展文档](https://docs.sillytavern.app/for-contributors/writing-extensions/)、[上下文接口](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/st-context.js)。
