# Henge · 词句修订

适用于 SillyTavern 的纯规则词句修订扩展。回复输出结束后按规则自动修订，或按正文顺序展示建议供你审阅。支持直接填写 JavaScript 正则、随机替换候选和酒馆替换宏。**不调用聊天模型，也不需要 API Key。分词在当前设备本地完成。**

扩展管理列表中的名称为 **Henge**；功能面板和魔棒入口仍显示「词句修订」。仓库名为 `sillytavern-text-revision`，安装地址保持不变。

## 功能介绍

| 功能 | 可以做什么 |
| --- | --- |
| 词语与句式检测 | 直接填写词语或句式正则，多个替换候选随机选择，留空删除 |
| 检测范围 | 提取正文标签；通过开始、结束文字排除标签或其他片段 |
| 逐句审阅 | 删除划线、新增和待改分色显示；点击整条选择或取消，右上角小铅笔编辑整句或标签之间的片段 |
| 应用与撤销 | 一次应用所选，更新保存的正文和当前回复版本，并支持撤销最近一次应用 |
| 检测记录 | 按轮次保留检出数量、涉及句段和已处理数量 |
| 手机与外观 | 加宽侧栏、魔棒菜单入口、可拖动悬浮球、日夜模式、四种界面美化、三组修订配色、背景透明度 |

版本变更见 [更新日志](CHANGELOG.md)。

## 安装

1. 在电脑或手机的酒馆中，打开「扩展」→「安装扩展」。
2. 粘贴 `https://github.com/Mint0oO/sillytavern-text-revision`，完成安装后刷新酒馆。
3. 点击输入框左侧的魔棒，在菜单中选择「词句修订」。也可从扩展设置打开，或输入 `/text-revision`。需要常驻入口时，在插件设置中开启「显示悬浮球」。

需要 SillyTavern 1.13.5 或较新版本，以及支持原生 dialog 的现代浏览器。若酒馆没有「安装扩展」，需要服务器管理员允许扩展安装；不需要在手机上安装 Node.js。

0.7.1 更新：规则编辑改为始终可见的「查找／替换为」两个框。直接填写正则，默认匹配全部；纯词表支持英文逗号分隔，替换候选随机选择，留空删除。移除新规则中的模式、分类、词性和附加条件设置，保留预览、统一自动／审阅设置、日志和撤销。

## 使用

- 回复完成后执行规则：标为自动的命中先应用并保存，剩余需要审阅的内容再打开侧栏。全部自动处理完成时不弹面板。重复完成通知合并处理；重 roll 后会检测新的回复。检测不调用模型，普通长度回复通常很快完成，保存时间取决于酒馆连接。
- 侧栏约占屏幕 80%，最窄 300 像素、最宽 1040 像素（不超出屏幕）。窄屏优先保留可读宽度。
- 点击有可应用建议的整条内容，可选择或取消；选中项有浅色背景和左侧细线。右上角小铅笔单独编辑，文字在其下方使用整行宽度。仅标记待改的条目需要先编辑，完成后才能选择应用。
- 规则的替换框留空表示删除；审阅候选中的「换一个」可选择其他替换词。
- 默认勾选有可应用建议的句子；取消勾选的句子不会改动。「应用所选」一次处理全部勾选项，保存成功后本轮不再显示角标。完全不想修改时可点「完成审阅」；剩余文字保留，之后仍可主动重新检测。
- 应用直接更新 `chat[].mes` 和当前 `swipes[swipe_id]`，调用酒馆保存，再读取服务器聊天核对。后续请求使用修改后的正文；其他版本不变。
- 「撤销」恢复本轮最近一次应用。切换聊天、回复版本、外部编辑或重新检测后，过期结果不能覆盖当前正文。
- 「记录」以检测轮次保存初始问题数、句子数与处理数；详情中的「修改日志」列出原文、替换结果、规则及自动／手动来源。每个聊天最多保留 30 轮，较大记录会更早清理旧轮次；累计轮数继续保留。
- 「规则」点击条目后原地向下展开编辑，再点一次收起。启用勾选位于最右侧，与展开操作独立。收起暂存输入，点击「保存规则」才保存；「取消」放弃该条草稿。
- 新规则直接填查找和替换，填法与示例见下方「填写查找和替换」。
- 「设置」支持极简、暖纸、青雾、淡紫四种界面美化，每种均可切换日间／夜间，另有三组修订配色与背景透明度。背景透明度使用夜间按钮右侧的短滑条，不改变文字透明度。
- 悬浮球缩小为 36 像素圆形，可选择跟随美化、石墨、浅蓝、鼠尾草、淡紫、奶茶配色，并独立调整整个图标的透明度；设置中提供实时预览。可用鼠标或手指拖动；位置在当前设备浏览器中记忆，屏幕变化时保持可见。轻点打开面板，拖动不会打开。
- 顶部显示「x处问题/x字段」；这里的字段指可独立修订的句段，不是标签个数。记录以 1、2、3 等数字表示检测轮次。

## 标签提取与排除

在「设置」中，「标签提取」和「内容排除」同排各占一半。点击对应入口，展开后编辑，点「保存」生效；「取消」不保存本次修改。两个功能各有开关，关闭时保留配置，方便以后再开启。

- **标签提取**：例如填 `content, maintext`，只检查对应标签内部的文字。使用逗号、中文逗号或换行分隔，也接受 `<content>` 或 `</content>`，大小写不敏感。支持 `Time-Space Module` 这样的带空格自定义标签名。关闭或留空表示整条回复；启用并填写了标签但回复中找不到时，会跳过，不会退回全文检测。
- **内容排除**：每行填写开始和结束文字，排除这两个标记及中间内容。例如 `<status>` → `</status>`、`image###` → `###`。可以添加和删除规则。排除优先于提取，包括正文里面的嵌套内容。
- 标准标签对支持大小写、属性和同名嵌套；其他分隔文字按原样匹配，区分大小写。请把需要保护的边界符号填完整。开始文字出现却没有对应结束文字时，会提示并停止检测。
- 默认提取标签为空；默认仅排除 `think`、`thinking`，以成对规则展示。旧版排除标签会自动转为可编辑规则；未改动过的五项默认列表会精简，自定义列表会保留。
- 不填写正文标签也可以检测：关闭或留空「标签提取」，再排除非正文内容，剩余文字就会参与检测。这是按配置筛选，不会自动判断剩余内容是不是正文；状态栏等内容如需跳过，须自行添加排除。

例如提取 `content`、排除 `status`：

```xml
<think>极其谨慎地思考。</think>
<content>
你拖着极其疲惫的身体，走进了旅店。
<status>情绪：极度不安</status>
壁炉旁的空位极具吸引力。
</content>
```

检测列表只出现「你拖着……」和「壁炉旁……」两段。`think`、`status` 里的内容以及全部标签原样保留。多个正文块会按原顺序处理；属性和原始换行不会被重新格式化。

标签、代码和排除内容构成编辑边界。一个句子中间含有这些内容时，会拆成独立句段，手动编辑也不会带上被保护内容。句式不会跨越这些边界匹配。配置的标签未闭合或配对错误时会停止检测并提示，修正原回复后再试。

保存新的检测范围后，需要重新检测；旧范围下的结果不会继续覆盖正文。标签设置仅改变检测范围，不会在未来请求中删除标签或排除内容。

## 填写查找和替换

规则编辑始终显示「查找」和「替换为」两个框，不再要求选择字词／句式、处理方式、词性或模板。新规则统一使用正则匹配，不调用 AI，也不需要生成脚本。

| 查找 | 替换为 | 效果 |
| --- | --- | --- |
| `死死` | 留空 | 删除每一处「死死」 |
| `死死地?` | 留空 | 删除「死死」和「死死地」 |
| `极其, 极致` | `十分, 很` | 每处随机换成「十分」或「很」 |
| `不是([^，。！？]+)，而是([^。！？]+)` | `$2` | 保留括号匹配的后半段 |
| `，(?:声音\|尾音)[^，。！？]*` | 留空 | 删除以「，声音」或「，尾音」开头、到下一个指定标点之前的片段 |

查找直接填写 JavaScript 正则的表达式部分，程序默认开启全部匹配（`g`），不用手动填写 `/…/g`。也接受完整 `/表达式/标志`，并保留你明确填写的标志；例如 `/死死/` 不含 `g`，只匹配每个连续可编辑正文块中的第一处。

纯词表可用**英文逗号或换行**分隔，前后空格会清理，重复项去重，较长词优先匹配。例如 `死死, 死死地` 不会残留一个「地」。含有括号、字符范围、反斜杠、`?`、`|` 等正则符号时按表达式原样解析，不拆其中的逗号。复杂正则的多个分支请用 `|`。中文逗号始终按正文标点保留。要查找实际的英文逗号，可写完整 `/甲,乙/g`，或转义逗号。

替换框默认用英文逗号或换行分隔候选，每一处命中独立随机选择；填一个候选就固定替换，留空删除。候选含英文逗号时可用英文双引号包住，例如 `"轻轻, 缓缓", 低声`。中文逗号不拆分。

勾选「整段替换」后，整个替换框是一份内容，英文逗号、空格和换行都原样保留；完全留空仍表示删除。需要替换为一个空格也可使用此选项。

`$1`、`$2`、`$<名称>` 保留对应捕获组；`$&`、`$0` 或 `{{match}}` 放回命中原文。替换模板还支持 `{{user}}`、`{{char}}`、`{{random::轻轻::缓缓}}`，调用酒馆的宏接口。包含英文逗号的宏可勾选「整段替换」或将整个候选用英文双引号包住。捕获的原文不会被再次作为宏执行。

「试一下」填写例句即可查看划线删除、新增文字及捕获内容，不会修改聊天；多个候选会随机选择，再点一次可重新试验。规则填写错误时保留草稿并提示原因。

「批量添加」每行一条，只填查找表示删除；查找和替换用一个 Tab 分隔，可从表格粘贴两列。每行自动判断删除／替换，不再单独选择模式。整批验证通过才保存，完全相同的规则跳过。

## 执行、日志与旧规则

规则列表上方统一选择「先审阅，再应用」或「回复结束后自动应用」，新建或重新保存的新格式规则跟随该设置。默认先审阅。设置中的「回复完成后执行规则」控制是否在回复结束时启动检测。

新格式正则先在允许处理的连续正文中匹配，再按命中位置组织审阅句段；支持跨句和跨行，`^`、`$` 指连续正文块的边界，换行匹配仍遵循正则本身的语法和标志。标签、代码和排除内容始终是不可跨越的边界。空位置匹配、无效表达式、检测超时（3 秒）或结果过大时会停止，不写入部分修改。

各条规则检测同一份原文，不会对替换结果循环套用规则。同一位置的等优先级重叠命中保留为人工审阅。自动结果保存后，仍需审阅的内容才打开面板；日志记录原文、结果、规则及自动／手动来源。候选结果在本轮固定，保存和刷新不会重新随机；最近一次应用可以撤销。

旧规则不会在升级时批量改写。旧字词／正则规则可以通过两个框编辑，保存后采用新规则的正文范围和统一处理设置；未编辑时继续使用原处理方式及范围。含 `{A}` 模板、词性、前后条件、优先级等的旧规则收进「旧版条件规则」，继续原样运行并可停用，展开只读查看；不再提供这些旧条件的编辑表单。需要改写时可新建正则规则替代。

新安装默认提供三条简单的程度词规则。升级用户保留已有规则和记录；旧检测结果可以查看，应用前需要重新检测。旧规则需要分词时仍使用随插件附带的 `jieba-wasm`，不会把词性模板自动转换为近似正则。

正则按你填写的文字结构匹配，不判断句意。词语和句式都建议先用例句检查实际命中范围。

## 数据与兼容

规则和外观保存在酒馆扩展设置，检测记录和原文快照保存在当前聊天元数据；这些记录不作为正文传给模型。导出聊天文件时会一并导出记录。原文快照用于对比和撤销，并非加密备份。

扩展没有外部分析服务、跟踪脚本、远程字体或聊天模型请求。启用分词规则时，会从插件自身目录加载约 4 MB 的本地分词组件（首次加载可能稍慢），不向外部发送正文；保存后仍向你自己的酒馆读取聊天进行核对。手机通过局域网 HTTP 访问时也能生成内部记录编号。

如果出现「未能确认保存成功」，请先检查网络。服务器可能已收到保存但核对请求失败；这时刷新聊天查看实际结果，再重新检测。扩展不会把无法确认的保存报告为成功。

同一聊天在多个设备同时编辑仍可能发生酒馆自身的并发冲突。建议只在一个设备上修改当前聊天。世界书、摘要、其他插件已缓存的旧内容不会被本扩展重写。

## 开发验证

无构建或安装依赖步骤。浏览器分词依赖已固定版本随 `vendor/jieba-wasm/` 分发，复制插件时必须包含此目录。仓库根目录的 manifest.json 可直接被酒馆安装。需要支持 WebAssembly 和正则匹配索引（`d` 标志）的现代浏览器。

```sh
npm test
npm run check
node scripts/dev-server.mjs
```

最后一个命令打开本地模拟酒馆界面：`http://127.0.0.1:8788`。模拟器可测试自动检测、保存、刷新读取、上下文正文和失败提示；它不是完整酒馆实例。`dev/` 与 `tests/` 不会由扩展入口加载。

接口依据：[酒馆扩展文档](https://docs.sillytavern.app/for-contributors/writing-extensions/)、[上下文接口](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/st-context.js)。
